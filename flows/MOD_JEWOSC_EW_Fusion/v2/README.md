## What v2 does — the JEWOSC analytic

The core EWOS problem is **mission-data fusion**: correlate incoming
ELINT/ES intercepts against the threat library, adjudicate ambiguous
cuts, and flag emitters that don't match anything on file (the
reprogramming trigger). That correlation is a **fuzzy parametric
match** (nearest emitter in normalized freq/PRI/PW space), *not* an
equality join — so it can't be a native Prep `SuperJoin`. It lives in a
Python Script node (`ew_intercept_fusion`), following the same pattern
as `ew_fusion` / `embassy_threat_join`: one primary feed in, reference
tables baked as literals.

```
ELINT Intercepts (local CSV, 500 cuts)
        │
        ▼
 EW Intercept Fusion  (Script node; bakes emitter library + EOB + platform MDF)
    • fuzzy match measured freq/PRI/PW → nearest library emitter
    • matched / ambiguous / unknown  → is_reprogram_trigger
    • nearest EOB site + affiliation + lethality + assoc_weapon
    • own-ship range/bearing + weapon-engagement-zone (in_wez)
    • platform coverage-gap count (how many MDFs are blind to this emitter)
        │
        ▼
 WriteToHyper → "MOD JEWOSC EW Fusion"  (33-column fused output)
```

## Sources
- **`local_csv`** — `synthetic_data/intercepts.csv` (500 ELINT/ES
  cuts: measured RF freq, PRI, pulse width, bearing, SNR, sensor id).
  The refreshable operational feed. Rides as a local CSV native
  connector (`.v1.LoadCsv` / textscan), not pushed to any server.

Baked into the fusion Script node as Python literals (slow-changing
reference, regenerated by `synthetic_data/generate_synthetic_ew.py`):
- **emitters.csv** — 25-emitter threat library (band, freq, PRI, PW,
  scan, ERP, modes, lethality, associated weapon, priority).
- **eob_sites.csv** — 40-site EOB laydown (emitter FK, lat/lon,
  echelon, mobility, affiliation, confidence, status).
- **platforms.csv** — 8 BLUE platforms with RWR/DAS fit + MDF version
  + coverage set (deliberately partial → coverage-gap analysis).

## Transformation
- **`ew_intercept_fusion`** — the fuzzy parametric correlation +
  geometry/WEZ + coverage-gap analytic described above. Template:
  `skill/templates/ew_intercept_fusion.py.j2`. Match tolerance **0.12**
  (calibrated: ~79% clean-cut correct-match, ~1% false triggers, 100%
  of genuine unknowns caught).

```bash
# 2. build + verify locally (TabPy must be up on :9099)
python3 -m skill.scripts.run_loop \
    --spec flows/MOD_JEWOSC_EW_Fusion/v2/spec.json \
    --flow-name MOD_JEWOSC_EW_Fusion --skip-scan

# self_consistency eval reports mean 0.0 under qa_tier=none (nothing to
# score); the Hyper is ground truth — inspect it directly.
```

Publishing is **not** done — awaiting greenlight. `--skip-scan` is
required (the INTERNAL scan surfaces unrelated site DSes otherwise).
`qa_tier` is `none`: the fusion Script node declares its own 33-col
output schema; inserting the deterministic Validator would silently
drop the 20 fused columns (Maestro honours each node's declared schema).
